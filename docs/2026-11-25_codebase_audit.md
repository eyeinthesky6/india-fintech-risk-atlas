# Atlas codebase audit — November 25, 2026

Audited `main` at `c9805bcdce0adfede9108cc6f7f58c01844154e6`. The build and release exports are consistent. The highest-priority defects are in notification security, misleading feedback receipts, and the way MCP assigns and cites regulatory controls. The site, local MCP server, and static releases can remain in place while those defects are repaired.

## Scope and evidence

- Traced the Astro and Starlight entry points, browser components, build-time parser, graph, machine exports, CLI, MCP tools and resources, tests, Python maintenance scripts, Git hooks, Actions workflows and correction Worker. Checked live configuration and deployment where the distinction mattered. The broad scan inventoried 178 tracked files, checked 36 supported source or configuration files and returned 30 review candidates. Findings below come from caller traces and targeted checks. Archived research, dependencies and generated output were excluded from the automated quality verdict. Generated data was compared directly.
- `npm run build`, Pagefind generation, the link validator, `npm test`, and the full and staged attestation checks passed. The offline citation gate reported 18 records and 38 URLs, with 26 skipped HTTP checks, 12 browser-queue entries and zero live HTTP probes. Neither pass establishes regulatory applicability or independent review. [PR validation](../.github/workflows/validate.yml) · [Pages deployment](https://github.com/eyeinthesky6/india-fintech-risk-atlas/actions/runs/45603117882)
- Exercised the MCP through its in-memory client with the shipped dataset. Compared actual built graph edges and references. Exercised the Worker in a local harness without network writes or issue creation. Read the live form configuration without submitting a correction. Checked the advertised expert sign-up URL, which returned HTTP 404.

## Fix first

### 1. Keep event text out of notification shell scripts

The contributor welcome and PR-ready workflows interpolate issue or PR titles into shell scripts in steps that use Telegram credentials. The contributor notification also runs for any opened issue despite claiming it announces a signup. Move event text through quoted environment variables, restrict signup alerts to the intended labels, and declare the permissions each job needs. The audit did not test attacks or establish credential exposure. [Contributor welcome](../.github/workflows/contributor-welcome.yml#L73) · [PR ready](../.github/workflows/pr-ready-notification.yml#L27) · [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use#use-an-intermediate-environment-variable)

### 2. Give correction submissions one truthful delivery contract

MCP posts to the browser-only Worker with a fixed dwell time and browser Origin, but has no Turnstile token. The actual Worker returned 403 in a local production-shaped check. The MCP test mocks the HTTP response and correctly proves receipt parsing. It cannot prove a report reaches private triage. The browser has the reverse problem. It announces delivery on any HTTP success, including the Worker's intentional `queued:false` response. The live page includes the Worker endpoint and Turnstile site key. An actual private queue delivery is unverified. [MCP submission](../mcp/src/server.js#L819) · [Worker acceptance](../workers/report-triage/src/worker.js#L147) · [Turnstile gate](../workers/report-triage/src/worker.js#L184) · [Browser receipt](../src/components/AtlasErrorReporter.astro#L724) · [Mocked MCP receipt test](../mcp/test/release.test.js#L83)

Keep the browser as the owner of private anonymous intake and check the structured queue receipt there. Route MCP directly to the existing private form or clearly labeled public GitHub fallback. Build an authenticated service intake only if direct MCP delivery becomes a product requirement. Keep Turnstile on the browser path. Disable remote posting in local preview by default and retain an explicitly configured Worker test path. The current local preview branch sits after the default live-endpoint branch. [Local submission paths](../src/components/AtlasErrorReporter.astro#L710) · [Worker setup](../workers/report-triage/README.md#L12)

### 3. Scope regulatory controls by explicit owner and use stable IDs

The role matcher treats labels such as `bank` as substrings. A real `remitter-bank` regulatory request returned entries owned by non-bank PSOs, acquiring banks, and card issuers. The same UPI-009 app and PSP control was `UPI-009-C49` in the all-role checklist and `UPI-009-C9` with the PSP filter. Those values are derived from the filtered row position and resemble ledger claim IDs. Add explicit owner IDs and keep the human-readable row label. Use aliases only to resolve the query role. Generate stable control IDs at the record, and keep them distinct from claim IDs. Test positive and negative matches for remitters, PSPs, issuers, acquirers and non-bank PSOs. [Role matching](../mcp/src/server.js#L42) · [Persona selection](../mcp/src/server.js#L519) · [Checklist IDs](../mcp/src/server.js#L580) · [Taxonomy](../src/taxonomy.json)

### 4. Carry source status and all links into machine exports

The structured exporter captures only the first URL on a numbered reference line. The current data loses NPCI About UPI from UPI-OVERVIEW, Cashfree Webhook Verification from UPI-005, NPCI Complaint Register from UPI-013, and the NPCI circulars index from UPI-014. The MCP tool describes its output as verified primary sources even though it returns the UPI-008 provisional bank mirror without explicit verification status. Its global deduplication also keeps only the first record using each URL. Wire reference parsing to all links and evidence-ledger claims. Carry source class, relevant result and locator, all citing records, and review stage. Keep shared-document graph edges separate from proof of a claim. [Reference parser](../scripts/build-atlas-data.js#L88) · [Source tool schema](../mcp/src/server.js#L165) · [Source aggregation](../mcp/src/server.js#L740) · [UPI-008 evidence](../research/evidence/UPI-008.md#L11)

## Suggested execution order

1. Repair or suspend the two notification steps that process untrusted titles. Gate readiness on actual checks and review state.
2. Fix browser receipt handling, route MCP corrections through the browser, and replace the broken expert signup path. Remove or relabel local acknowledgment as part of that feedback work.
3. Add typed control ownership and stable IDs. Correct citation extraction and verification metadata, and strengthen tests across actual outputs.
4. Resolve the public-draft policy conflict. Repair staged validation and watcher reporting. Consolidate parsers, remove confirmed dead declarations, and update active docs after behavior is proven.

The audit changed no application, automation, deployment, or regulation record. It does not certify the corpus, prove delivery into private triage, or infer that any workflow flaw was used.

## Remediation

- The public research policy now allows labeled drafts. **Human checked** reflects an independent human evidence check. Maintainers retain the reviewer identity mapping separately from the status displayed on the site. [Policy](SECTION_WORKFLOW.md#publication-policy)
- MCP uses explicit control owners, stable control IDs, and citation-level evidence metadata. Correction drafts open the browser reporting route, and the browser checks for an actual queue receipt. [MCP contract tests](../mcp/test/release.test.js)
- The workflow fixes use event values as quoted arguments, announce approval separately from merge readiness, and record feed failures and notification receipts. GitHub labels required by the issue forms and intake workflows were added.
- The Worker rate-limit migration passed its local SQLite test and Wrangler build-only dry run. Live private delivery was outside this verification. [Worker test](../workers/report-triage/test/triage.test.js)
